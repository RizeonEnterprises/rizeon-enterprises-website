# Rizeon Enterprises

Agency website on a headless stack:

- **Frontend:** Next.js 16 (App Router, TypeScript, Tailwind CSS v4, Cache Components)
- **CMS:** Sanity Studio v6, a standalone app in [`/studio`](studio)
- **Glue:** [`next-sanity`](https://github.com/sanity-io/next-sanity) with Sanity Live, so published content shows up on the site within seconds, with no rebuild or webhook

## Project layout

```
.
├── app/                   Next.js routes (UI not built yet)
├── sanity/                Data layer used by the Next.js app
│   ├── env.ts             Reads/validates NEXT_PUBLIC_SANITY_* env vars
│   ├── client.ts          Base Sanity client (published content, API CDN)
│   ├── live.ts            defineLive(): sanityFetch, <SanityLive />, cachedSanityFetch
│   ├── queries.ts         GROQ queries (defineQuery)
│   ├── data.ts            Typed fetchers for pages: getBlogPost(slug), getPortfolioProjects(), …
│   ├── image.ts           urlFor(image) → Sanity CDN URL
│   └── types.ts           GENERATED by Sanity TypeGen; don't edit
└── studio/                Sanity Studio (own package.json)
    ├── sanity.config.ts
    ├── sanity.cli.ts      Also holds the TypeGen config
    ├── structure.ts       Studio sidebar: Portfolio, Blog posts, Authors
    └── schemaTypes/
        ├── documents/     portfolioProject, blogPost, author
        ├── objects/       blockContent (shared rich text)
        └── fields/        imageWithAlt (image + required alt text)
```

## Content model

| Type | Fields |
| --- | --- |
| `portfolioProject` | title, slug, mainImage (+alt), challenge, solution, result, body (rich text) |
| `blogPost` | title, slug, author → `author`, publishedAt, mainImage (+alt), metaDescription, body (rich text) |
| `author` | name, slug, role, image (+alt), bio. Referenced by blog posts so one author is reused across posts |

The rich text (`blockContent`) has H2–H4 (no H1, because the page title is the H1), quotes, bullet and numbered lists, bold/italic/code, links (with an "open in new tab" option), and inline images with required alt text. The meta description warns editors outside 70–160 characters.

## First-time setup

Requires Node.js ≥ 22.12.

1. **Install dependencies** (two packages: app and studio):

   ```bash
   npm install
   ```

   ```bash
   npm run studio:install
   ```

2. **Create or link a Sanity project.** This step needs your Sanity account, so it can't be scripted. From `studio/`:

   ```bash
   cd studio && npx sanity login
   ```

   ```bash
   npx sanity init --bare
   ```

   `--bare` creates (or selects) a project and dataset and prints their IDs without overwriting the files in this folder. You can also create a project at <https://www.sanity.io/manage>.

3. **Fill in env files** with the project ID and dataset:

   - `studio/.env` (copy from `studio/.env.example`)
   - `.env.local` (copy from `.env.example`)

4. **Allow the site to talk to Sanity Live** (browser connection from localhost):

   ```bash
   cd studio && npx sanity cors add http://localhost:3000
   ```

   Add your production domain the same way before going live.

## Day-to-day

| Command | What it does |
| --- | --- |
| `npm run dev` | Next.js on http://localhost:3000 |
| `npm run studio` | Sanity Studio on http://localhost:3333 |
| `npm run typegen` | Regenerate `sanity/types.ts` after changing a schema or a query |
| `npm run typecheck` | Generate Next route types, then `tsc --noEmit` |
| `npm run lint` | ESLint for the app (`npm --prefix studio run lint` for the Studio) |
| `cd studio && npx sanity deploy` | Host the Studio at `<name>.sanity.studio` |

## Fetching content in a page

```tsx
// app/blog/[slug]/page.tsx (example, not created yet)
import { notFound } from "next/navigation";
import { getBlogPost, getBlogPostSlugs } from "@/sanity/data";

export async function generateStaticParams() {
  return getBlogPostSlugs();
}

export default async function Page(props: PageProps<"/blog/[slug]">) {
  const { slug } = await props.params;
  const post = await getBlogPost(slug); // fully typed from TypeGen
  if (!post) notFound();
  // render post.title, post.body with <PortableText value={post.body} /> from "next-sanity", …
}
```

How caching works: every fetcher in `sanity/data.ts` goes through `cachedSanityFetch` (the single `'use cache'` boundary). `sanityFetch` tags results with Sanity sync tags, and `<SanityLive />` in `app/layout.tsx` revalidates just those tags when content is published.
